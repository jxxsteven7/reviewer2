# Reviewer 2

[English](README.md) | **简体中文**

**学术圈的在线多人聚会游戏合集。** 每人用自己的手机加入房间。不用注册就能加入；推荐注册账号，可以保存头像和战绩。

## 这是什么

- **学术主题**：审稿、投稿、组会、基金、答辩。
- **共享词库**：按领域划分的学术术语，由社区贡献。
- **为同行而做**：不以盈利为目标，不放广告。

### 第一个游戏：团队猜词

两个课题组（红组、蓝组）围绕 25 个学术术语对战。每组的 PI 知道哪些牌属于自己组，但只能给出**一个简短的提示 + 一个数字**，学生们根据提示去翻牌。翻到无关论文或对方的牌，回合结束；翻到**二号审稿人**，当场被拒稿，本组直接判负。

暂名**双盲**（Double Blind），代码里的模块叫 `keywords`，规则见 [docs/games/keywords.md](docs/games/keywords.md)。

## 特点

- 中英双语
- **中国大陆**可玩：不用 Google 服务和公共 CDN
- 手机优先；能在微信里玩
- 锁屏断线后自动重连，回到原来的座位
- 服务器权威：队员即使打开开发者工具，也看不到未翻开牌的颜色
- 账号可选：头像、战绩、好友和好友称号、学术头衔和公开主页；见[隐私](#隐私)
- 比赛：连打几局计分，并授予称号
- 公开房间：用账号和陌生人一起玩，可以举报不守规矩的玩家
- AI 玩家（内测中）：一号审稿人可以当一组的导师或学生，给真人出主意，也能替掉线的玩家打完他的回合，还有自己的主页，是 0 号玩家；有账号的人可以在首页和它练一局，其余三个座位由它坐满；见[隐私](#隐私)

## 隐私

我们对玩家的承诺：

- **推荐注册，但不强制。** 什么都不用填就能玩：游客不起名字，在每个房间里按进房先后叫游客1、游客2……；注册账号后，头像、战绩、头衔和称号会一直保存，上次怎么设置房间也会记住，下次开房直接用，只有你自己看得到。
- **只有好友**能看到你是否在线、是否在房间里、房间里是否在对局、对方的哪些好友也和你在同一个房间，房间号只在房间公开或者对方也在这个房间里时才显示。同一房间里的玩家照旧能看到谁和自己在一起；其他人都看不到这些。
- **加好友时附的一句话**只有被加的人能看到，请求被处理或撤回后就删除。**你给好友改的备注**只有你自己看得到：好友不会知道，别人也看不到。
- **好友称号**按你和每位好友一起打过的局算，比如共同一作，只有你自己看得到：在你的好友列表和好友的主页上。
- **你的公开主页**对任何打开它的人显示用户名、头像、学术头衔、称号、玩家编号和注册日期，以及你自己填的链接和一句简介；战绩、反馈被采纳的次数各有一个开关，默认显示，关掉就不显示（在改为默认显示以前注册的账号，要自己打开才显示）。点赞数所有人可见，点赞的人只有你能看到。有账号的人在好友搜索里输入你完整的用户名，或者粘贴主页链接，就能找到它；只输入用户名的一部分找不到。
- **密码**只存单向哈希，谁都读不出原文，运营者也不行。
- **账号的邮箱从不保存。** 服务器只存它的一个带密钥的指纹，用来核对邮箱和发送找回密码的邮件。
- **日志里没有 IP 地址和名字。** 统计只有数字：人数、房间数和国家。
- **建议**由项目的运营者阅读，你写的内容可能会公开成 GitHub issue，署名的话带上你的名字，联系方式绝不公开。被采纳的建议一定会公开成 issue，并以你的署名（选了匿名就是匿名玩家）列在首页的反馈贡献里。登录后署名，建议里只记你的账号、不存名字，按账号现在的头像和用户名显示，点开是你的公开主页，注销后显示为「已注销玩家」；没有账号就自己填一个署名用的名字。登录时提的建议会关联你的账号，不管署没署名，账号上都会记被采纳的次数。联系方式按原样保存，90 天后删除。建议本身会作为项目的建议存档保留；只有运营者丢弃的（比如垃圾信息）才会在丢弃 30 天后删除。
- **公开房间里的举报**只有运营者能看到，永久保留。举报会记下谁举报了谁、被举报者当时在房间里的名字、房间号和举报人填写的说明。
- **每一局都会被记录**：不论怎么结束、谁来玩，一局都会永久记录，用了主持自定义词的局也一样：整盘牌、每一步操作和时间（比如每条提示和翻牌）、组内讨论里说的话（包括终局后组内的复盘讨论，直到下一局开始），以及是谁做的；有账号的玩家，记录和账号关联。谁进房、谁离开，掉线的玩家因此超时，以及这局怎么结束的，也会记录。点了没翻的牌、快捷表情和一时的掉线不记录。学生在牌上做的预标不记每一次改动，只在本组翻牌、每回合结束和对局结束时记下当时的样子，回看里也没有。导师标出的提示想指的牌，对局中谁都看不到，赛后房间里的人都能看到。有账号的玩家可以回看打完的局：整盘牌、提示词和两组的人，回看里没有组内讨论。回放里不存任何名字：打开时按账号现在的用户名和头像显示，你给好友改了备注的显示备注，注销的账号显示为「已注销玩家」，游客按房间里的编号显示。
- **记录的用途**：训练和评测游戏里的 AI 玩家，也用于研究，可能在去掉名字和账号后公开成数据集。注册时会请你同意这一条，账号会记下你同意的是第几版说明、什么时候同意的；游客进房间前会再提醒一次。有 AI 参与的局（AI 玩家，或者替掉线的人托管），记录会保存 AI 的每一步、它用的模型和给出的理由；这样的局不加学术积分，也不算连胜、称号和好友称号。
- **注销账号**会删掉它的全部数据，只有用它提过的建议（被采纳的仍列在首页上，署名的显示为「已注销玩家」；已经发成 GitHub issue 的，issue 上的名字不会改）、它发出的和针对它的举报，以及它参与过的那些局的记录（别人也在局里）会保留，但不再和账号关联：回放里它显示为「已注销玩家」，不带名字；它在组内讨论里说的话和其他对局记录一样匿名保留；备份里的副本到期后也会消失。

## 技术栈

| 部分 | 选型 |
|---|---|
| 语言 | TypeScript，npm workspace |
| 前端 | Vue 3 + Vite，vue-i18n |
| 后端 | Node.js + Socket.IO |
| 存储 | 房间在内存里；反馈和账号在 SQLite（`node:sqlite`）里；头像存成文件 |
| 测试 | Vitest，端到端用 Playwright |
| 部署 | 一个 Node 进程、一个端口，外加一个小发信程序 |

## 目录结构

| 路径 | 内容 |
|---|---|
| `client/src/` | Vue 应用：`core/` 共用部分，`games/<game>/` 各游戏的界面，`locales/` 全部界面文字 |
| `server/src/` | 服务器：`core/` 房间，`games/<game>/` 各游戏的规则，`accounts/` 账号，`store/` 数据库 |
| `shared/` | 前后端共用的类型和规则 |
| `mailer/` | 发送账号邮件的程序 |
| `agent/` | 向语言模型要 AI 玩家下一步的程序 |
| `words/` | 词库，每个领域一个 JSON 文件 |
| `e2e/`、`scripts/`、`docs/` | 端到端测试、仓库检查脚本、文档 |

## 本地运行

需要 [Node.js](https://nodejs.org) 24.15 或更高，但不能是 25。

```bash
npm install   # also turns on the git hooks
npm run dev   # front end on http://localhost:5173, server on port 3000
```

本地运行不需要任何外部服务的密钥。要试邮件功能，把 `.env.example` 复制成 `.env`，再在 `npm run dev` 旁边运行 `npm run dev:mailer`：邮件只会打印出来，不会发送。AI 玩家还需要一个语言模型，并运行 `npm run dev:agent`。其他命令、在手机上测试和环境变量见 [docs/development.md](docs/development.md)。

## 参与贡献

规则见 **[CONTRIBUTING.md](CONTRIBUTING.md)**（英文），简单说：

1. `main` 受保护：所有改动都从自己的分支或 fork 发 Pull Request。
2. 每个 PR 都要作者以外的人 review（维护者自己只改[给人读的文档](docs/rules/versioning.md#docs-for-people)的 PR 除外），通过且 CI 绿了之后由协作者合并。
3. 提交里不出现 AI 或 agent 署名。
4. 仓库内容使用英文；这份 README 是唯一的翻译文件。
5. 每个 PR squash 合并成一个提交；除了只改给人读的文档的 PR，都带版本号，见 [docs/rules/versioning.md](docs/rules/versioning.md)。

AI 助手读 `AGENTS.md`。

建议被采纳的玩家会署名或以匿名方式列在首页的反馈贡献里，每一条都是带 [adopted](https://github.com/jxxsteven7/reviewer2/issues?q=label%3Aadopted) 标签的 GitHub issue。维护者对其他人的致谢写在 [ACKNOWLEDGMENTS.md](ACKNOWLEDGMENTS.md) 里，赞助者列在 [SPONSORS.md](SPONSORS.md) 里，首页上都有。
